Data Days · Microsoft Fabric Data Engineer (DP-700)

Fil rouge des exercices | AdventureWorks

Un exercice guidé par session, du Jour 1 au Jour 3 : nous construisons progressivement une solution Fabric complète | ingestion, transformation, sécurité, temps réel, supervision et optimisation | autour du jeu de données AdventureWorks.

Le jeu de données : AdventureWorksLT

AdventureWorks est la base d'exemple de Microsoft pour un fabricant de vélos fictif. Nous utilisons la version allégée AdventureWorksLT, disponible en base Azure SQL d'exemple ou en export CSV, avec ses tables principales :

- SalesLT.Customer | clients (nom, email, téléphone, territoire)

- SalesLT.Product / SalesLT.ProductCategory | catalogue produits

- SalesLT.SalesOrderHeader / SalesLT.SalesOrderDetail | commandes et lignes de commande

- SalesLT.Address / SalesLT.CustomerAddress | adresses de livraison

Scénario fil rouge : nous jouons le rôle de l'équipe data d'AdventureWorks Cycles, chargée de construire la plateforme analytique de l'entreprise dans Microsoft Fabric.

Prérequis communs

- Un locataire Microsoft 365 avec une capacité Fabric d'essai (Trial) activée.

- Un accès à la base d'exemple AdventureWorksLT (Azure SQL Database exemple, ou export CSV fourni par le formateur).

- Les droits nécessaires pour créer des espaces de travail dans le locataire de formation.

Jour 2 · Session 2 · Batch Transformation

Transformer les commandes avec Spark

> Exercice | Notebook Spark et table Delta optimisée

Durée : 20 minutesFormat : binôme
Nettoyer et agréger les commandes AdventureWorks avec PySpark.

- Créer un notebook dans l'espace de travail, attaché à AdvWorksLakehouse.

- Charger bronze/SalesOrderHeader et bronze/SalesOrderDetail dans deux DataFrames.

----
orders = spark.read.load("Files/bronze/SalesOrderHeader")
lines  = spark.read.load("Files/bronze/SalesOrderDetail")
sales = (lines.join(orders, "SalesOrderID")
.groupBy("ProductID")
.agg({"LineTotal": "sum", "OrderQty": "sum"}))
sales.write.format("delta").mode("overwrite").saveAsTable("silver_sales_by_product")
----

- Exécuter le notebook et vérifier la table silver_sales_by_product créée.

- Activer OptimizeWrite sur cette table et relancer une écriture pour observer la réduction du nombre de fichiers.

Resultat : Résultat attendu : une table Delta silver_sales_by_product agrégée par produit, écrite avec OptimizeWrite activé.

Jour 2 · Session 3 · Batch Transformation | Suite

Organiser AdventureWorks en architecture médaillon

> Exercice | Couches Bronze, Silver, Gold et rapport

Durée : 25 minutesFormat : binôme
Finaliser la couche Gold prête pour l'analyse commerciale.

- Vérifier que bronze (brut) et silver_sales_by_product (nettoyé) existent déjà.

- Créer la couche Gold avec une table gold_sales_summary combinant produits, catégories et ventes :

----
CREATE TABLE gold_sales_summary AS
SELECT c.Name AS Category, p.Name AS Product,
s.sum_LineTotal AS Revenue, s.sum_OrderQty AS UnitsSold
FROM silver_sales_by_product s
JOIN Product p ON p.ProductID = s.ProductID
JOIN ProductCategory c ON c.ProductCategoryID = p.ProductCategoryID;
----

- Restreindre l'accès à bronze aux ingénieurs données uniquement (rôle Fabric OneLake).

- Créer un rapport Power BI simple sur gold_sales_summary montrant le revenu par catégorie.

Resultat : Résultat attendu : une couche Gold interrogeable, un accès Bronze restreint, et un premier rapport de revenu par catégorie.

Jour 2 · Session 4 · Real-Time Transformation

Simuler un flux de commandes en temps réel

> Exercice | Eventstream, Eventhouse et requêtes KQL

Durée : 25 minutesFormat : binôme
Simuler l'arrivée de nouvelles commandes AdventureWorks en flux continu.

- Créer un Eventstream nommé AdvWorksOrdersStream avec la source d'exemple Générateur d'événements de test, ou publier manuellement des lignes de SalesOrderHeader comme événements JSON.

- Ajouter une transformation Filtre pour ne garder que les commandes dont le montant total dépasse 500 $.

- Ajouter une fenêtre bascule de 1 minute agrégeant le nombre de commandes et le montant total.

- Router la sortie vers un nouvel Eventhouse nommé AdvWorksRealtime, table OrdersLive.

- Écrire une requête KQL isolant les commandes des 10 dernières minutes :

----
OrdersLive
| where ingestion_time() &gt; ago(10m)
| summarize TotalRevenue = sum(TotalDue), Orders = count() by bin(ingestion_time(), 1m)
----

Resultat : Résultat attendu : un flux de commandes filtré et agrégé, stocké dans un Eventhouse, interrogeable en KQL.
